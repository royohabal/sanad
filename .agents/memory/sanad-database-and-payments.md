SANAD uses MongoDB as the application's primary database, replacing PostgreSQL for runtime. Keep PostgreSQL intact as a rollback/source copy. The development database was migrated; production data has not been migrated and must be checked before publishing.

Public child-QR transfers and parent/personal wallet top-ups remain clearly labelled simulations. Worker tips use Stripe-hosted test Checkout only: keep SANAD records and balances in KWD, convert the displayed KWD amount to USD cents using the selected ExchangeRate-API Open Access rate, and persist the exact quote snapshot. Never silently fall back to a simulated tip when conversion or Stripe fails. This rate source says its rates are informational and not suitable for actual financial transactions; do not enable live payments with it. No live payments or payouts have been verified. Family management and cash-out actions require Clerk sign-in; platform management requires an allowlisted admin. No first-admin email has been approved. Child cash-out must not be marked paid until a real payout flow exists. Worker withdrawal “paid” is an admin-only demo status that never moves money.

Use the same Clerk identity for parent, worker, and company accounts; do not add global worker/company roles. Approved companies create worker profiles and invite workers by verified Clerk email; workers cannot self-register or self-assign. Deactivation disables the worker dashboard's public QR but retains the worker's history. Public worker QR tipping stays no-login and requires Stripe test Checkout; verify the Stripe session or signed webhook before crediting, and keep settlement idempotent. Worker tips and monthly settlements are company-scoped; independent worker cash-out is disabled. Never transfer a legacy independent balance into a company settlement or vice versa.

**Why:** The user explicitly chose MongoDB and secure sign-in, requested company-managed worker invitations with no self-registration or independent cash-out, requested KWD accounting with USD Stripe test Checkout for worker tips and no simulated tip fallback, and requested explicit handling of legacy tips and separate worker/company balances. The selected ExchangeRate-API Open Access source is acceptable for test mode only and must not be used to enable live money movement.

**How to apply:** Keep PostgreSQL intact; enforce worker ownership, active invitation status, and companyId scope on the server; verify MongoDB health without logging credentials; for worker tips, keep KWD as the stored/display currency, use a fresh attributed KWD-to-USD quote and USD cents in Stripe test mode, and fail closed on rate or Checkout errors. Never credit from the success URL alone; verify Stripe payment status and signed webhooks idempotently. Preserve explicit simulation labels for other flows; do not enable live payments with the informational rate source or bootstrap an admin without an email the user has explicitly selected.
